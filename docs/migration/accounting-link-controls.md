# Accounting Styled Link Migration

Mokly's `MockLink asChild` replaces Accounting's custom navigation HTML
conversion for styled controls. Use this guide when Accounting adopts a package
release containing the API. The package implementation does not publish a
release or update Accounting automatically.

## Author Links

Replace the consumer's `Nav` wrapper with an explicit catalogue link:

```tsx
import { Button } from "@firna/ui";
import { MockLink } from "@mokly/mokly";

const noop = () => {};

<MockLink asChild to="return-overview">
  <Button tone="primary" onPress={noop}>
    Continue
  </Button>
</MockLink>;
```

Retain `onPress={noop}` when Firna requires it to render an enabled button.
It does not perform navigation: Mokly builds a native anchor with the resolved
destination. Real disabled or busy props must remain on the component and be
reflected in its rendered HTML.

Put styles, ids, accessibility labels, and other attributes on the child. Its
rendered root must be one supported HTML control without another interactive
control inside it or a focusable parent wrapper. Native browser button chrome
and JavaScript-only hover/pressed effects are not reproduced. Retain explicit
widths for block buttons and avoid styles that depend on the original tag name.

## Retire Consumer Navigation Conversion

After all intended controls use the package API, remove Accounting's custom
navigation HTML converter and navigation click script. Keep theme wrapping,
Firna components, React Native Web style collection, and product styles in the
consumer renderer. Ordinary metadata-only `data-nav-href` wrappers do not become
clickable automatically; each intended interaction must be authored explicitly.

Rebuild and check the catalogue, inspect the generated diff, and smoke-test
pointer and keyboard navigation in Browse, use-case flows, standalone files,
and Review snapshots. Include enabled, disabled, and busy controls in both
viewports. A renderer migration can still change generated bytes across many
screens even when their appearance is unchanged; inspect that migration
separately from changes to product screens.

See the [styled link controls contract](../protocol/mokly-link-controls.md)
for the complete API and validation rules, and the
[framework migration inventory](./accounting-framework-inventory.md) for the
wider Accounting ownership boundary.
